# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [3.0.2] - 2026-11-18

### Fixed

- `LED_TIME_ENC()` корректно насыщает очень большие значения, не переполняя
  промежуточное округление.
- ID событий packed-паттерна остаётся постоянным от первого цикла до остановки,
  даже если все его каналы отсоединены.
- `led_packed_once()` обновляет однословную команду и запускает FSM в одной
  критической секции; getters времени и остатка эффекта защищены при ISR-модели.
- `led_effect_remaining()` возвращает 0 после `led_init()`.

### Changed

- Обновлены размеры прошивок по актуальной сборке: demo — 3944 B Flash / 412 B
  RAM, rates — 3348 B Flash / 408 B RAM.
- Сравнение объектного кода `-Os` по 24 конфигурациям: сумма `text + data`
  не выросла (от 0 до 128 B меньше). Это объектные размеры; полный размер
  firmware зависит от линковки и окружения.

## [3.0.1] - 2026-09-28

Проход по размеру кода на CH32V003 (-Os RV32EC). Сигнатуры API и ABI
не менялись; исправлены описанные ниже граничные случаи без изменения
таймингов и общего порядка вызовов callback.

### Changed

- **Владение снимается без повторного обхода каналов.** На выходе из
  `led_advance()` по `LED_TICKS_FOREVER` таймерных паттернов заведомо
  нет, поэтому `cur_owner` обнуляется одной записью. Раньше этот путь
  вызывал `patterns_active()`, то есть ещё один полный проход по
  каналам на каждом «спящем» advance.
- **Одна функция гашения каналов вместо трёх копий цикла.**
  `off_by_mode(mode, or_higher)` обслуживает `packed_reset()`,
  `stop_effect_inner()` и `stop_all_patterns()`: тела циклов у них были
  идентичны и отличались только сравниваемым режимом.
- **Внутренние обращения к каналам идут через указатель.** Мутаторы
  (`on_for_locked`, `blink_locked`, `play_locked`) и все обходы
  `leds[]` используют `led_state_t *s` вместо индексации: на RV32EC
  `leds[id]` стоит `slli/add/slli`, а внутри цикла с вызовом функции ещё
  и spill базы массива в стек на каждой итерации.
- **`eff_multi_blink()` — одно условие вместо двух.** DOUBLE и TRIPLE
  описываются общей формулой `fx_phase < lit && (fx_phase % 4) < 2`,
  различаются только `lit` (6 или 10) и длина цикла.
- **`eff_running_hold()`** не дублирует выражение маски: парковка
  `fx_pos` на последней позиции даёт правильный «край» в обоих
  направлениях. Ветви с одинаковым телом (сброс счётчиков) слиты.
- **`eff_group_blink()`** берёт длительность фазы из `eff_period[] / 2`
  вместо цепочки `if/else` с тремя константами.
- **`led_toggle()`** делает один вызов `set_mode_level()` вместо ветви на
  `set_mode_off()`/`set_mode_on()` — это обычный хвостовой вызов без
  `__riscv_save_0`/`restore_0`.
- **`led_flash_and_fade()`** считает длительность вычитанием (шаг 10 тиков)
  вместо умножения `(count-1-i)*10` в каждой итерации.
- **`eff_period[]` сужена до `uint8_t`** (максимум 145 при `LED_COUNT = 8`)
  — на 12 байт меньше ROM. Рядом добавлены `LED_SA(...)`-проверки, чтобы
  будущее увеличение периода ломало сборку, а не переполняло таблицу.
- **`packed_apply()`/`packed_take()`** проверяют младший бит маски и сдвигают
  её вправо на канал, вместо вычисления `1u << i` на каждой итерации.

### Fixed

- Сборка с `-Wconversion` была не чистой: `uint8_t` в выражении
  `(effect_mask >> i) & 1u` повышался до `int`, и пересечение с `1u`
  давало знаковое преобразование. Это ломало CI (`-Werror`) на всех
  конфигурациях. Добавлено явное приведение к `unsigned`.
- Комментарий в `examples/test_ch32v003` утверждал, что `led_stop_owner()`
  гасит «только каналы маяка» и SOS на LED1 продолжается. Это неверно:
  владение глобальное (одна метка на индикатор), per-pattern владельца не
  существует, поэтому функция гасит **все** таймерные паттерны (см.
  `led.h`, `led_stop_owner`). Комментарий и текст сообщения приведены в
  соответствие с фактическим поведением; поведение не менялось.
- ID packed-событий берётся из первой маски и сохраняется для всех циклов и
  завершения, даже если от паттерна отсоединены все каналы.
- `led_packed_once()` теперь меняет однословную команду и запускает FSM внутри
  одной критической секции. Запросы времени/остатка эффекта также защищены от
  чтения неполного значения при ISR-модели.
- `led_effect_remaining()` возвращает 0 после `led_init()`. `LED_TIME_ENC()`
  насыщает длительности выше максимума без переполнения округляющего сложения.

### Пример demo: UART-диагностика и самотест (макросы)

`examples/test_ch32v003` получил вывод в UART (USART1, TX = PD5, 115200)
и самотест, выполняемый на целевом МК. Оба включаются макросами и по
умолчанию **равны 0** — обычная сборка (`pio run -e ch32v003`) не
содержит ни диагностики, ни её кода:

- `DEMO_UART=0` (по умолчанию) — убрать `printf` полностью:
  11520 -> 4572 Б Flash. vfprintf тянет за собой ещё и malloc с кучей; при 0
  в линковке не остаётся ни одного символа printf/malloc.
- `DEMO_SELFTEST=0` (по умолчанию) — убрать самотест и его 384 Б буферов
  трассировки: ещё ~0.6 КБ Flash. При обоих флагах в 0 прошивка демо
  совпадает с версией до диагностики байт в байт по размеру (3968 Б);
  ровно эти флаги и стоят в `build_flags` окружения `ch32v003`.

Флаги также заданы в самом `main.c` (`#ifndef DEMO_UART / #define ... 0`),
так что «чистый» демо-сценарий получается и при сборке мимо PlatformIO.
Включить диагностику — поменять `0` на `1` в `build_flags` окружения
`ch32v003`; переопределять через `PLATFORMIO_BUILD_FLAGS` нельзя:
PlatformIO склеивает переменную окружения с `build_flags` и получится
предупреждение `DEMO_UART redefined`.

Самотест проверяет на железе: инвариант батчинга
`led_advance(1) x 40 == led_advance(40)` (сравнивается вся
последовательность вызовов callback, не только конечное состояние),
`led_ticks_until_next() != 0` и семантику владения. Он не зависит от
`printf`: при `DEMO_UART=0` провал сообщается миганием LED3 (число
вспышек = битовая маска упавших тестов), так что регресс виден без кабеля.

## [3.0.0] - 2026-09-27

Релиз под задачу порта на «спящий» МК с аналоговым каналом индикации.
Основное: **событийная модель времени** (`led_advance` + `led_ticks_until_next`),
**уровневый выход** вместо вкл/выкл, **владение индикатором**,
**упакованные команды** 32 бит, **события** переходов.

### Breaking changes (миграция 2.x → 3.0)

- **Тип callback-а вывода**: `void (*)(uint8_t id, bool state)` →
  `void (*)(uint8_t id, uint8_t level)`. Callback перестаёт быть
  логическим: он получает требуемый **уровень** вывода
  (0 = гасить, 1..LED_LEVEL_MAX = «горит»). Для обычного GPIO
  достаточно `if (level) set_bits(); else reset_bits();`.
- **`led_step_t`**: поле `bool state` заменено на `uint8_t level`.
  Запись последовательностей: `LED_STEP_ON(n)` / `LED_STEP_OFF(n)`
  работают как раньше, `LED_STEP_LVL(level, n)` задаёт произвольный
  уровень. Инициализаторы вида `{ true, 10 }` нужно заменить на
  `{ 1, 10 }`.
- **`led_toggle()`** по-прежнему переключает по фактическому состоянию
  вывода, но «состояние» теперь это уровень: ненулевой уровень
  считается горящим.
- **`led_process()`** сохранён и определён как `led_advance(1)`;
  переносить код не нужно. Все тайминги задаются в тиках, как раньше.

Миграция API по шагам:
1. В callback'е заменить `bool state` на `uint8_t level`
   (в теле — `if (level)` вместо `if (state)`).
2. Последовательности: `{ true, 10 }` → `{ 1, 10 }`,
   `{ false, 5 }` → `{ 0, 5 }`.
3. Всё. Остальной API 2.x совместим.

### Added

- **Пример `examples/rates_ch32v003`**: четыре диода с разными частотами
  (1 раз в 4 с / 1 раз в 2 с / 1 раз в 1 с / 2 раза в 1 с) при скважности
  50 % — второй пример репозитория, собирается из корня окружением
  `pio run -e ch32v003-rates` (свой `platformio.ini` у примеров не бывает:
  окружение выбирает каталог примера через `build_src_filter`). Тайминги
  этих четырёх частот зафиксированы тестом `test_independent_rates()`.
- **Событийная модель времени** (главное нововведение):
  - `void led_advance(uint32_t ticks)` — продвигает все конечные
    автоматы на `ticks` тиков. Если за один вызов пересечено несколько
    переходов, они применяются **все и по порядку** (детерминированно,
    без «провала» переходов).
  - `uint32_t led_ticks_until_next(void)` — сколько тиков можно проспать
    до ближайшего **изменения вывода**; `LED_TICKS_FOREVER`, если
    таймерных паттернов нет.
  - Инвариант против дрейфа: `led_advance(1)` × N тождественно
    `led_advance(N)` — идентичная последовательность вызовов callback и
    одинаковое конечное состояние. Тики без переходов проматываются
    за O(1) на тик, поэтому `led_advance(1000)` не дороже
    `led_advance(1)`.
  - Рецепт «спящего» хоста — в `led.h` и `docs/LED_LIBRARY.md`.
- **Уровневый выход**:
  - `led_set_level(id, level)` — статический уровень (основной API
    аналогового канала: TURBO/MID/MAX = уровни 5/3/1).
  - `led_blink_level(id, on_level, on_ticks, off_level, off_ticks)` —
    двухфазное мигание произвольными уровнями.
  - `led_step_t.level` + `LED_STEP_LVL(level, ticks)`.
  - `uint8_t led_get_level(id)` — текущий уровень вывода.
  - Макрос `LED_LEVEL_MAX` (1..255, по умолчанию 7) документирует
    диапазон уровней аппаратуры.
- **Владение индикатором** (арбитраж подсистем, а не выводов):
  `led_set_owner()`, `led_claim()`, `led_release()`,
  `led_stop_owner()`, `led_pattern_active()`. Владение глобальное для
  подсистемы; снимается само, когда все таймерные паттерны завершились.
  Индикаторы: `LED_OWNER_UI / BEACON / WARNING / STROBE`.
- **Упакованные команды** (`LED_USE_PACKED_COMMANDS`, по умолчанию 1):
  формат 32 бит (4 байта на пару фаз + счётчик повторов + маска
  каналов), длительности кодируются макросами времени
  (`LED_TIME_ENC`, деление только при сборке). API:
  `led_packed_run()`, `led_packed_once()`, `led_packed_stop()`.
  Системные команды: `LED_SYS_STOP`, `LED_SYS_REP_START`,
  `LED_SYS_REP_AT(n)`, обработка на границе массива + guard от
  зацикливания вырожденных таблиц.
- **События** (`LED_USE_EVENTS`, по умолчанию **0** — не раздувает
  базовую сборку; владение работает и без него):
  `led_set_event_callback()` + `LED_EV_CYCLE_START`, `LED_EV_PATTERN_END`,
  `LED_EV_STATE`. Событие `LED_EV_CYCLE_START` приходит на старте
  паттерна и на каждом его круге (`arg` = номер повтора).
- **`LED_ARRAY_LEN(arr)`** — длина массива для `led_packed_run()`
  (и как синоним `LED_STEP_ARRAY_LEN`).
- **`LED_SEQ()` / `LED_SEQ_LOOP()`** — `led_sequence_t` без ручного
  `sizeof`.
- Стартовая задержка последовательности: ведущий шаг
  `LED_STEP_OFF(n)` = «начать через n тиков» (отдельного API нет).
- Формулировка ТЗ «вспышка на текущей яркости фонаря» реализована как
  `led_blink_level(id, current_level, on_ticks, 0, off_ticks)`.

### Fixed

- **`led_get_level()` работает без callback'а**: кэш уровней обновляется
  всегда, а не только при наличии обработчика (в 2.x `led_is_on()`
  зависел от подключённого callback'а).
- **Инвариант `advance(1)×N == advance(N)` для фазы BLINK**: смена фазы
  больше не «откладывается» до следующего тика при пакетном продвижении
  (уровень доводится в том же проходе).
- **Каналы упакованного паттерна не гасились пакетным продвижением**:
  добавлен режим `LED_MODE_PACKED`, иначе `led_advance(n)` возвращал каналу
  уровень 0 (в режиме OFF) вместо уровня фазы (регрессия поймана тестом
  длинных таймеров).
- Первый «полный драйв» выводов после `led_init()` /
  `led_set_callback()` / `led_refresh()` занимает одно и то же место в
  потоке вызовов callback независимо от разбиения времени на advance.

### Performance

- **Экономия Flash: переработка ядра под один таймер на канал.** У канала
  теперь ровно один таймер `timer` («тики до следующего изменения вывода»),
  ноль означает «таймерного режима нет». Из этого следуют три вещи:
  - `next_change_ticks()`, `idle_ticks()` и `tick_one()` работают без
    `switch` по режиму (режим проверяется только в момент перехода);
  - `ON_FOR` больше не отдельный обработчик: это просто «статичный уровень
    с таймером», `BLINK` и `SEQUENCE` — два оставшихся случая перехода;
  - номер фазы BLINK и признак зацикливания SEQUENCE живут в битах 3 и 4
    поля `mode` — отдельного `flags` нет.
  Служебные биты маскируются в `led_get_mode()` (`LED_M_MODE`).
- `led_blink()` стал обёрткой над `led_blink_level()` (общий код фаз вместо
  второй копии), `led_packed_once()` — обёрткой над `led_packed_run()` над
  таблицей из одного слова.
- Автомат упакованных команд похудел: слова читаются через кэш `pc_cmd`,
  маска каналов — прямо из слова, объединение масок (`pc_live`) не нужно
  (список забранных каналов = «режим `LED_MODE_PACKED`»), переход обеих фаз
  декодируется одним выражением, `packed_next()` имеет один выход.
- `led_init()` обнуляет только состояние (таймер/уровень/режим) — параметры
  режима записывают сами мутаторы; состояние эффекта обнуляет
  `led_start_effect()`, PRNG сбрасывается явно.
- Каналы забираются упакованным паттерном один раз (по маске первой
  команды), поэтому per-LED вызов отрывает канал до конца паттерна, а
  команды с более широкой маской не могут «отжать» чужой канал.
- `led_advance(n)` для n без переходов — O(1) на тик вместо O(LED_COUNT)
  (полный перебор каналов делается только на тиках с переходами).
- Измерения (CH32V003, -Os, RV32EC; вклад = сборка с библиотекой минус
  сборка без неё), было → стало:
  - 1 канал, только упакованные команды: 1464 → **1244 Б** Flash (RAM 48 Б);
  - 3 канала, то же: 1796 → **1532 Б** (68 Б);
  - 4 канала, все модули: 2988 → **2660 Б** (124 Б);
  - прошивка демо целиком: 4444 → **4116 Б**.
- Уровневый кэш вывода — 1 байт на канал (вместо битовой маски),
  поэтому уровни > 1 не требуют дополнительных полей.
- `LED_PACKED_GUARD` ограничивает число системных команд за один
  переход: вырожденная таблица с нулевыми фазами не может зависнуть
  внутри одного `led_advance()`.

### Docs

- Документация переписана под новую модель времени, уровни, владение и
  упакованные команды; добавлены разделы «Спящий хост», «Уровни»,
  «Владение», «Упакованные команды», «События».
- Ресурсы переизмерены и приведены честные цифры (см. README).

### Known limitations

- **Точность `LED_TIME_ENC`**: 6-битная мантисса при шаге `4^shift`
  даёт относительную погрешность не хуже **1/32 ≈ 3.1 %** (это
  теоретический предел формата; оценка «1.3 %» из ТЗ недостижима при
  зафиксированной раскладке битов). Значения до 63 тиков кодируются
  точно, на 1 тик ошибки нет. Время задаётся в тиках, поэтому на
  паттерны это не влияет.
- Глобальные эффекты тикают по одному тику (быстрый проход по ним
  потребовал бы деления в `led_advance()`); `led_ticks_until_next()`
  для активного эффекта возвращает 1. Инвариант advance при этом
  сохраняется.
- `_Static_assert` раскладки команды используется в C11+, а при
  компиляции как C99 — эквивалентный массив отрицательного размера
  (та же проверка на этапе компиляции, строгий C99 не нарушается).

## [2.0.0] - 2026-09-03

Результат полного аудита библиотеки. Исправления дефектов, найденные
верификацией на хосте (run-length анализ эффектов, тайминги, матрица
конфигураций), а также новые API и инфраструктура тестов.

### Fixed
- **`led_start_effect()` идемпотентен**: повторный запуск уже активного
  эффекта больше не сбрасывает фазу. Раньше вызов в цикле опроса
  «замораживал» эффект на первой фазе (все диоды застывали включёнными
  для EMERGENCY/PAIR/ALTERNATING).
- **Таймер повторов тикает независимо от диодов**: если пользователь
  «оторвал» все диоды от эффекта (led_on/led_blink/led_play), таймер
  `led_start_effect_for()` теперь всё равно завершает эффект вовремя.
  Раньше запрос состояния эффекта залипал на «активен» навсегда.
- **RUNNING_FWD_HOLD / RUNNING_BWD_HOLD**: устранена паразитная вспышка
  крайнего диода на 1 тик при переходе фазы через 0 — все циклы эффекта
  теперь идентичны; первая позиция бега горит полные 10 тиков.
- **RUNNING_PP**: выдержка первой позиции теперь 10 тиков (было 9) —
  маска выдаётся до продвижения счётчиков, как в остальных эффектах.
- **Последний кадр таймированного эффекта** отрабатывает полный период
  (раньше обрезался на 1 тик из-за остановки в том же тике).
- **`led_toggle()`** переключает по фактическому состоянию вывода:
  горящий в ON_FOR/BLINK/SEQUENCE/EFFECT диод гаснет, а не «включается
  ещё раз». Раньше toggle горящего диода терял авто-выключение.
- **Смена callback** (`led_set_callback()`) инвалидирует кэш GPIO — новый
  обработчик получает полную картину состояний на ближайшем тике.
- **`led_init()`** сохраняет callback (повторная инициализация больше не
  глушит вывод молча), инвалидирует кэш GPIO (первый тик гасит все диоды)
  и сбрасывает PRNG RANDOM_FLASH — состояние библиотеки после
  `led_init()` полностью воспроизводимо.
- **`led_start_effect()` с некорректным/отключённым значением** больше не
  может оставить диоды зависшими в EFFECT-режиме с NULL-обработчиком.
- Убраны мёртвые ветки `if (counter > 0)` в обработчиках BLINK и
  дублированное условие в `led_start_effect()` (cppcheck).

### Changed (breaking)
- **`LED_COUNT`** теперь переопределяется из сборочной системы
  (`-DLED_COUNT=n`), допустимый диапазон **1..8** проверяется `#error`.
  Все маски и периоды эффектов производны от `LED_COUNT`.
- **Удалён макрос `handle_leds`** (загрязнение глобального пространства имён).
- **`led_init()`** больше не сбрасывает callback — используйте
  `led_set_callback(NULL)`.
- **`led_effect_is_running()` заменён** на пару запросов:
  `led_effect_active()` (работает ли эффект вообще, включая бесконечные)
  и `led_effect_remaining()` (остаток тиков, `LED_EFFECT_FOREVER` — бесконечно).
- **Мутаторы обёрнуты в `LED_ENTER_CRITICAL()`/`LED_EXIT_CRITICAL()`**
  (по умолчанию — пусто). Определите макросы для сценария
  «led_process() в прерывании». led_process() критической секцией не
  оборачивается намеренно.
- Шаг последовательности с `ticks == 0` трактуется как 1 тик
  (нулевая длительность в тиковой модели невозможна), зависание невозможно.
- Убрана зависимость от libc: `memset` заменён явным сбросом полей,
  `<string.h>` больше не включается (freestanding-совместимость).

### Added
- **`led_restart_effect_for(effect, repeats)`** — принудительный перезапуск
  эффекта с нулевой фазы (для повторного запуска по событию).
- **`led_effect_active()`**, **`led_effect_remaining()`** — запросы состояния
  эффекта (см. breaking выше).
- **`led_get_mode(id)`**, **`led_is_on(id)`** — запросы состояния диода.
- **`led_refresh()`** — принудительная пересинхронизация выводов после
  внешних изменений GPIO (переинициализация порта, сон).
- **Отключаемые модули** `LED_USE_*`: SEQUENCES, EFFECTS (+ 6 групп эффектов).
  Значения `led_effect_t` не меняются — ABI стабилен.
- **Макросы версии** `LED_LIB_VERSION_MAJOR/MINOR/PATCH/VERSION`.
- **Хост-тесты** `test/test_led_lib` (самодостаточный раннер, ~100 проверок):
  `pio test -e native` либо `gcc test/test_led_lib/test_led_lib.c src/led.c`.
  Проверяются тайминги всех режимов, run-length всех эффектов, матрица
  конфигураций LED_COUNT × LED_USE_*.
- **CI** (GitHub Actions): хост-тесты по матрице конфигураций с `-Werror`,
  строгая проверка `-pedantic-errors`, сборка прошивки CH32V003.
- Периоды эффектов производны от `LED_COUNT` (раньше таблица была
  рассчитана только на 4 диода).

### Performance
- Записи таблиц `eff_table[]`/`eff_period[]` и функции эффектов
  исключаются из прошивки вместе с отключёнными модулями (до ~0.7 КБ
  на CH32V003, если эффекты не используются).
- RAM состояния диодов сокращается с 20 до 8 байт на диод при
  `LED_USE_SEQUENCES=0`.

### Packaging
- Удалён несуществующий механизм `.pioignore`; состав пакета задаётся
  полем `export.exclude` в `library.json` (публикуются только
  `include/`, `src/`, `examples/`, `library.json`, `README.md`,
  `LICENSE`, `CHANGELOG.md`).
- Удалён неработающий ключ верхнего уровня `src_filter` (PlatformIO
  читает только `build.srcFilter`; защита от рекурсии обеспечивается
  стандартным лейаутом библиотеки `src/`).
- Версия манифеста и теги синхронизированы (2.0.0).

### Docs
- Синхронизированы с кодом: описание внутреннего состояния, точные
  цифры RAM (100 Б) и Flash (~2.4 КБ), инструкция по LED_COUNT,
  честное описание модели вызовов и ограничений ISR.

## [1.0.1] - 2026-08-30

### Fixed
- README minimal example: `led_start_effect_for()` must come BEFORE per-LED
  calls (`led_blink`, `led_on_for`) — the effect claims all non-EFFECT LEDs,
  and per-LED calls after it "detach" the specific LEDs. Clarified that the
  API never blocks; `led_process()` drives the state machines.
- Demo: use the corrected effect-then-per-LED example in `main.c`
  (LED2+LED3 emergency flashes, LED0 blink, LED1 on-for 5 s).

## [1.0.0] - 2026-08-30

### Added
- First public release.
- Per-LED state machines: OFF, ON, ON_FOR, BLINK, SEQUENCE (`led_play`)
  for 4 independent LEDs on any bare-metal MCU (C99, no RTOS, no malloc).
- 12 built-in global effects with auto-stop repeats
  (`led_start_effect` / `led_start_effect_for`) and a dispatch table
  (`eff_table[]`) for easy extension.
- Minimal RAM footprint: ~97 bytes for library state (20 bytes per LED).
- GPIO access only through a user callback (`led_set_fn`) — the library
  contains no hardware-specific code.
- CH32V003 demo (PlatformIO, WCH NoneOS SDK) in `examples/test_ch32v003`.

### Performance
- GPIO writes are cached (`out_mask` + `driven_mask`): the callback fires
  only on an actual pin change or the first drive per LED.
- Effects advance shared incremental counters (`fx_phase/fx_pos/fx_cnt`,
  `fx_adv()`) instead of dividing a global tick counter — no software
  divide/multiply (`__udivsi3`/`__mulsi3`) in the 60 Hz hot path.
- Effects return a bitmask of LED states (`uint8_t (*)(void)`) rather than
  writing a `bool` array; built-in effects merged into shared functions
  (13 → 6) which are selected by `cur_effect`.
