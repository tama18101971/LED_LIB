## Обзор

Библиотека управляет **1–8** независимыми светодиодами для bare-metal
микроконтроллеров (без RTOS). Каждый диод имеет собственный конечный автомат
и может выполнять свой сценарий независимо от остальных.

**Ключевые принципы:**
- Весь код выполняется в одной функции `led_process()`, вызываемой пользователем
- Нет таймеров, нет delay(), нет malloc, нет зависимости от libc —
   только статическая память (~100 байт при LED_COUNT = 4)
- Доступ к GPIO только через пользовательский callback
- C99, портируемость: STM32, CH32V003, AVR, ESP32

**Что умеет:**
- Включение/выключение отдельных диодов
- Включение на заданное время (auto-off)
- Непрерывное мигание
- Воспроизведение пользовательских последовательностей (SOS, двойное мигание и т.д.)
- 12 встроенных глобальных эффектов (бегущий огонь, аварийная сигнализация, удержание и т.д.)
- Эффект на N повторов с авто-остановкой (`led_start_effect_for`)
- Идемпотентный запуск эффектов и принудительный перезапуск (`led_restart_effect_for`)
- Запрос состояния (`led_get_mode`, `led_is_on`, `led_any_led_active`,
  `led_effect_active`, `led_effect_remaining`)
- Вспышка с последовательным погасанием (`led_flash_and_fade`)
- Отключаемые модули (`LED_USE_*`) для экономии Flash

## Быстрый старт

### 1. Подключение библиотеки

Скопируйте `include/led.h` и `src/led.c` в свой проект (или подключите
репозиторий как PlatformIO-библиотеку — см. `library.json`).

### 2. Реализация callback для GPIO

```c
#include "led.h"

void led_hw_set(uint8_t id, bool state) {
    // STM32:
    // HAL_GPIO_WritePin(LED_PORT, led_pins[id],
    //                   state ? GPIO_PIN_SET : GPIO_PIN_RESET);

    // AVR:
    // if (state) PORTB |= (1 << id);
    // else       PORTB &= ~(1 << id);

    // CH32V003:
    // if (state) GPIO_SetBits(GPIOC, (1 << (4 + id)));
    // else       GPIO_ResetBits(GPIOC, (1 << (4 + id)));
}
```

### 3. Инициализация и главный цикл

```c
int main(void) {
    SystemInit();
    gpio_init();

    led_init();
    led_set_callback(led_hw_set);

    led_blink(0, 15, 15);  // ~240 мс вкл / ~240 мс выкл (тик ≈ 16 мс)

    while (1) {
        led_process();     // 60 раз в секунду
        Delay_Ms(16);
    }
}
```

## Модель вызовов и потокобезопасность

Внутреннее состояние — обычные static-переменные. Поддерживаются два сценария:

**1) Один контекст (по умолчанию).** Все `led_*()` вызываются из одного
контекста (обычно главный цикл). Настройка не требуется.

**2) `led_process()` в прерывании, остальной API — из главного цикла.**
Определите критическую секцию до подключения `led.h`:

```c
#define LED_ENTER_CRITICAL()  __disable_irq()
#define LED_EXIT_CRITICAL()   __enable_irq()
#include "led.h"
```

или через флаги сборки:

```ini
build_flags =
    -DLED_ENTER_CRITICAL='portENTER_CRITICAL()'
    -DLED_EXIT_CRITICAL='portEXIT_CRITICAL()'
```

Мутаторы (`led_on`, `led_blink`, `led_play`, эффекты, `led_init`,
`led_set_callback`, `led_refresh`) становятся атомарными относительно
обработчика. Обратите внимание: пользовательский GPIO-callback может
вызываться с запрещёнными прерываниями — держите его коротким.

**Не поддерживается:** вызов мутаторов из прерывания, когда
`led_process()` работает в главном цикле. `led_process()` критической
секцией не оборачивается намеренно — это сохраняет минимальную задержку
реакции на прерывания.

## Конфигурация

| Макрос | По умолчанию | Описание |
|--------|--------------|----------|
| `LED_COUNT` | 4 | Число диодов, 1..8 (проверка `#error`) |
| `LED_USE_SEQUENCES` | 1 | `led_play()` и режим SEQUENCE |
| `LED_USE_EFFECTS` | 1 | вся подсистема эффектов |
| `LED_USE_RUNNING_EFFECTS` | 1 | RUNNING_FWD / BWD / CIRCLE |
| `LED_USE_PINGPONG_EFFECT` | 1 (0 при LED_COUNT=1) | RUNNING_PP |
| `LED_USE_BLINK_EFFECTS` | 1 | EMERGENCY / PAIR_BLINK / ALTERNATING |
| `LED_USE_MULTI_BLINK_EFFECTS` | 1 | DOUBLE_BLINK / TRIPLE_BLINK |
| `LED_USE_RANDOM_EFFECT` | 1 | RANDOM_FLASH |
| `LED_USE_HOLD_EFFECTS` | 1 | RUNNING_FWD/BWD_HOLD |
| `LED_ENTER/EXIT_CRITICAL` | пусто | критическая секция |

Значения enum `led_effect_t` не зависят от отключённых модулей: попытка
запустить отключённый эффект игнорируется, ABI стабилен.

## API справочник

### Инициализация

```c
void led_init(void);
```
Сбрасывает все диоды в OFF, обнуляет счётчики и PRNG, останавливает эффект.
Callback **сохраняется**, кэш GPIO инвалидируется — первый `led_process()`
принудительно перезапишет все выводы. Отключить вывод: `led_set_callback(NULL)`.

```c
void led_set_callback(led_set_fn fn);
```
Устанавливает callback. Инвалидирует кэш состояний: новый обработчик получит
полную картину (по одному вызову на диод) на ближайшем `led_process()`.

```c
void led_refresh(void);
```
Принудительная пересинхронизация выводов без смены логического состояния.
Нужна, если выводы могли измениться в обход библиотеки (переинициализация
порта, выход из сна, смена альтернативной функции пина).

**Тип callback:**
```c
typedef void (*led_set_fn)(uint8_t id, bool state);
```
Callback вызывается только при фактическом изменении вывода.
Из callback нельзя вызывать функции `led_*()` — библиотека не реентерабельна.

### led_process

```c
void led_process(void);
```
Обрабатывает все диоды за один тик. Вызывается с постоянной частотой
(обычно 60 Гц). Все тайминги API задаются в тиках.

### Управление отдельным LED

#### led_on / led_off

```c
void led_on(uint8_t id);
void led_off(uint8_t id);
```

Мгновенное включение/выключение. **Отменяет** любой текущий эффект,
мигание или последовательность на этом LED. Вне диапазона — игнорируется.

#### led_toggle

```c
void led_toggle(uint8_t id);
```

Переключает по **фактическому состоянию вывода**: если диод горит — гаснет
(режим OFF), иначе — включается (режим ON). Работает предсказуемо в любом
режиме: горящий диод в ON_FOR, BLINK или EFFECT гаснет (авто-таймеры при
этом теряются — диод переходит в явный режим OFF/ON).

#### led_on_for

```c
void led_on_for(uint8_t id, uint16_t ticks);
```

Включает LED на заданное число тиков, потом автоматически выключает.

```c
led_on_for(1, 300);   // LED1 горит 300 тиков (5 с при ровно 60 Гц)
led_on_for(2, 60);    // LED2 горит 1 секунду
led_on_for(3, 0);     // мгновенное выключение
```

| Тики | Время (60 Гц) | Время (тик 16 мс, как в демо) |
|------|-------|-------|
| 1 | 16.7 мс | 16 мс |
| 6 | 100 мс | 96 мс |
| 15 | 250 мс | 240 мс |
| 60 | 1 с | 0.96 с |
| 300 | 5 с | 4.8 с |

#### led_blink

```c
void led_blink(uint8_t id, uint16_t on_ticks, uint16_t off_ticks);
```

Непрерывное мигание с заданными фазами. Если любая из фаз равна 0 — диод
выключается.

```c
led_blink(0, 15, 15);   // ~240/240 мс в демо с тиком 16 мс
led_blink(0, 5, 25);    // короткая вспышка
```

#### led_flash_and_fade

```c
void led_flash_and_fade(uint8_t count);
```

Включает диоды 0..count-1 одновременно, держит 1 секунду (60 тиков), затем
гасит по одному с интервалом 10 тиков: **LED[count-1] гаснет первым
(60 тиков), LED[0] — последним**. Останавливает активный эффект и гасит
диоды с индексом >= count.

## Работа с последовательностями

### Определение

```c
typedef struct {
    bool     state;   // true = включить
    uint16_t ticks;   // длительность (0 трактуется как 1 тик)
} led_step_t;

typedef struct {
    const led_step_t *steps;   // массив шагов
    uint16_t          count;   // количество шагов
    bool              loop;    // true = зациклить
} led_sequence_t;
```

> **Важно:** библиотека хранит указатель на массив шагов и не копирует его.
> Массив должен существовать всё время воспроизведения — используйте
> `static const`, а не локальные переменные.

### Пример: SOS

```c
static const led_step_t sos[] = {
    LED_STEP_ON(6),   LED_STEP_OFF(6),
    LED_STEP_ON(6),   LED_STEP_OFF(6),
    LED_STEP_ON(6),   LED_STEP_OFF(18),
    LED_STEP_ON(18),  LED_STEP_OFF(6),
    LED_STEP_ON(18),  LED_STEP_OFF(6),
    LED_STEP_ON(18),  LED_STEP_OFF(18),
    LED_STEP_ON(6),   LED_STEP_OFF(6),
    LED_STEP_ON(6),   LED_STEP_OFF(6),
    LED_STEP_ON(6),   LED_STEP_OFF(60),
};
static const led_sequence_t sos_seq = {
    sos, sizeof(sos) / sizeof(sos[0]), true
};

led_play(2, &sos_seq);
```

Длительность шага с `ticks == 0` трактуется как 1 тик.

### Управление

```c
led_off(id);         // остановить и выключить
led_play(id, &new_seq);   // заменить последовательность
```

## Глобальные эффекты

Эффекты управляют **всеми диодами** одновременно. Значения enum не зависят
от конфигурации; попытка запустить эффект из отключённого модуля
(`LED_USE_* = 0`) игнорируется.

### Встроенные эффекты

| Эффект | Описание | Цикл |
|--------|----------|------|
| `LED_EFFECT_RUNNING_FWD` | Бегущий огонь 0→N-1 | N×10 тиков |
| `LED_EFFECT_RUNNING_BWD` | Бегущий огонь N-1→0 | N×10 |
| `LED_EFFECT_RUNNING_PP` | Туда-обратно | (2N−2)×10 |
| `LED_EFFECT_RUNNING_CIRCLE` | Бегущий огонь быстрее | N×8 |
| `LED_EFFECT_PAIR_BLINK` | Чёт/нечет в противофазе | 30 |
| `LED_EFFECT_EMERGENCY` | Все диоды 5/5 тиков | 10 |
| `LED_EFFECT_RANDOM_FLASH` | Случайные вспышки (xorshift32) | 1 тик |
| `LED_EFFECT_DOUBLE_BLINK` | Двойное мигание | 80 |
| `LED_EFFECT_TRIPLE_BLINK` | Тройное мигание | 105 |
| `LED_EFFECT_ALTERNATING` | Чёт/нечет, медленно | 40 |
| `LED_EFFECT_RUNNING_FWD_HOLD` | Бег + пауза 20 + удержание 45 | N×10+65 |
| `LED_EFFECT_RUNNING_BWD_HOLD` | То же назад | N×10+65 |

При LED_COUNT = 4 это даёт таблицу 40/40/60/32/30/10/1/80/105/40/105/105.
Маски чёт/нечет производятся от `LED_COUNT` и работают для любого N.

### Запуск и остановка

```c
led_start_effect(LED_EFFECT_RUNNING_FWD);          // бесконечно, идемпотентно
led_start_effect_for(LED_EFFECT_EMERGENCY, 5);     // 5 вспышек, авто-стоп
led_start_effect_for(LED_EFFECT_RUNNING_FWD, 0);   // 0 = бесконечно
led_restart_effect_for(LED_EFFECT_RUNNING_FWD, 1); // принудительно с нулевой фазы
led_stop_effect();                                  // вручную
```

**Идемпотентность.** `led_start_effect()` / `led_start_effect_for()` не
изменяют состояние, если этот же эффект уже активен, — их безопасно вызывать
в цикле опроса. Для принудительного перезапуска (кнопка, новая ошибка)
используйте `led_restart_effect_for()`.

**Диоды можно «оторвать»** от эффекта любым per-LED вызовом — остальные
продолжат эффект. Вернуть диод в эффект без перезапуска нельзя.

### Запросы состояния

```c
if (led_effect_active()) { /* эффект работает (в т.ч. бесконечный) */ }
uint32_t r = led_effect_remaining();  /* остаток тиков;
                                         LED_EFFECT_FOREVER — бесконечный;
                                         0 — эффект завершается/завершён */
```

### Приоритет: per-LED vs эффект

```c
led_start_effect(LED_EFFECT_RUNNING_FWD);
led_blink(2, 15, 15);   // LED2 «оторвался» от эффекта

led_stop_effect();      // LED0, LED1, LED3 -> OFF; LED2 продолжает мигать
```

## Приоритеты управления

| Вызов | Что происходит |
|-------|----------------|
| `led_on(id)` | Любой предыдущий режим отменяется → ON |
| `led_off(id)` | Любой предыдущий режим отменяется → OFF |
| `led_toggle(id)` | Горит (фактически) → OFF, иначе → ON |
| `led_on_for(id, N)` | Отменяет предыдущий → ON_FOR |
| `led_blink(id, ...)` | Отменяет предыдущий → BLINK |
| `led_play(id, seq)` | Отменяет предыдущий → SEQUENCE |
| `led_start_effect(...)` | Все диоды в EFFECT (идемпотентно) |
| `led_start_effect_for(..., N)` | Все диоды в EFFECT на N циклов |
| `led_restart_effect_for(..., N)` | Перезапуск эффекта с нулевой фазы |
| `led_stop_effect()` | Диоды в EFFECT → OFF |
| `led_flash_and_fade(count)` | count диодов ON 1 с → гаснут по одному |
| `led_refresh()` | Кэш GPIO сброшен, выводы перезапишутся |

## Примеры использования

### Базовый

```c
#include "led.h"

void led_hw_set(uint8_t id, bool state) { /* GPIO */ }

int main(void) {
    SystemInit();
    led_init();
    led_set_callback(led_hw_set);

    led_on(0);
    led_blink(1, 15, 15);
    led_on_for(2, 300);

    while (1) {
        led_process();
        Delay_Ms(16);
    }
}
```

### Эффект по событию (идемпотентный опрос)

```c
while (1) {
    if (alarm_active()) {
        /* перезапускать не нужно: пока эффект уже активен, вызов ничего
           не меняет; чтобы «оживить» индикацию по каждому событию — */
        led_restart_effect_for(LED_EFFECT_EMERGENCY, 10);
    }
    led_process();
    Delay_Ms(16);
}
```

### led_process() из SysTick (CH32V003 / RISC-V)

```c
/* led.h:
#define LED_ENTER_CRITICAL()  __disable_irq()
#define LED_EXIT_CRITICAL()   __enable_irq()
*/

/* прерывание таймера, 60 Гц: */
void TIMER_IRQHandler(void) {
    /* флаг/сброс флага прерывания */
    led_process();
}

int main(void) {
    ...
    led_init();
    led_set_callback(led_hw_set);
    led_blink(0, 15, 15);
    for (;;) { /* главный цикл свободен для другой работы */ }
}
```

## Портирование на другие МК

1. **Скопировать** `include/led.h` и `src/led.c`
2. **Реализовать** callback `led_hw_set()` для вашего GPIO
3. **Настроить** частоту вызова `led_process()` (60 Гц)

**STM32 (HAL):**
```c
static const uint16_t led_pins[] = { GPIO_PIN_0, GPIO_PIN_1, GPIO_PIN_2, GPIO_PIN_3 };

void led_hw_set(uint8_t id, bool state) {
    if (id >= LED_COUNT) return;
    HAL_GPIO_WritePin(GPIOC, led_pins[id],
                      state ? GPIO_PIN_SET : GPIO_PIN_RESET);
}
```

**AVR (ATmega328P):**
```c
void led_hw_set(uint8_t id, bool state) {
    if (id >= LED_COUNT) return;
    if (state) PORTB |= (1 << id);
    else       PORTB &= ~(1 << id);
}
```

**ESP32 (ESP-IDF):**
```c
void led_hw_set(uint8_t id, bool state) {
    gpio_set_level(GPIO_NUM_2 + id, state ? 1 : 0);
}
```

## Потребление ресурсов

### RAM (LED_COUNT = 4, все модули включены)

| Компонент | Размер |
|-----------|--------|
| `leds[4]` (упакованы, 20 Б на диод) | 80 Б |
| `hw_set` (4), `effect_remaining` (4), `rng` (4) | 12 Б |
| `out_mask`, `driven_mask`, `cur_effect`, `fx_*` (6 × 1 Б) | 6 Б |
| **Итого** (с учётом выравнивания) | **100 Б** |

При `LED_USE_SEQUENCES=0`: 8 Б на диод → **57 Б**.
При `LED_COUNT=1` и отключённых модулях — от ~13 Б.

### Flash

| Конфигурация | Размер |
|--------------|--------|
| Всё включено (LED_COUNT = 4) | ~2.4 КБ |
| Только ручные режимы (`LED_USE_EFFECTS=0`) | ~1.2 КБ |
| + `LED_USE_SEQUENCES=0` | ~0.9 КБ |

Фактический размер зависит от платформы; неиспользуемые функции
выбрасываются линкером (`-ffunction-sections -fdata-sections` +
`--gc-sections`).

### Время выполнения led_process()

Константное, O(LED_COUNT): фиксированный цикл по диодам + один вызов
эффекта. Нет делений, умножений и переменных циклов.

## Часто задаваемые вопросы

### Почему 60 Гц?

1 тик = 16.7 мс — компромисс между плавностью и нагрузкой. Демо использует
`Delay_Ms(16)` (≈62 Гц, тик ≈16 мс). Библиотеке всё равно: она считает тики.
Все тайминги задаются в тиках и масштабируются с частотой вызова.

### Как добавить 5-й LED?

Задайте `LED_COUNT` при сборке — редактировать файлы библиотеки не нужно:

```ini
build_flags = -DLED_COUNT=5
```

Допустимо 1..8 (внутренние маски — `uint8_t`). Все эффекты, включая
паттерны «все» и «чёт/нечет», автоматически подстраиваются.

### Что будет при редком вызове led_process()?

Эффекты замедлятся пропорционально — тайминги заданы в тиках, а не в секундах.

### Как остановить мигание / последовательность / эффект?

```c
led_off(0);        // конкретный диод
led_stop_effect(); // все диоды в EFFECT
```

### Можно ли поставить эффект на паузу?

Встроенной паузы нет. Варианты: остановить и перезапустить
(`led_stop_effect()` / `led_restart_effect_for()`), либо «оторвать»
отдельные диоды per-LED вызовом.
