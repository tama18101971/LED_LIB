## Обзор

Библиотека управляет **1–8** независимыми светодиодами для bare-metal
микроконтроллеров (без RTOS). Каждый канал имеет собственный конечный автомат
и может выполнять свой сценарий независимо от остальных.

**Ключевые принципы:**

- **Тик задаёт хост.** Библиотека не имеет внутренних источников времени:
  хост сам решает, когда двигать время вперёд, и может спать между
  продвижениями.
- **Выход — это уровень** 0..`LED_LEVEL_MAX`, а не вкл/выкл: один и тот же
  API обслуживает и GPIO-включатель, и DAC с 7 ступенями яркости.
- Нет таймеров, нет delay(), нет malloc, нет зависимости от libc —
  только статическая память.
- Доступ к выводу только через пользовательский callback.
- C99, портируемость: STM32, CH32V003, AVR, ESP32, любой bare-metal MCU.

**Что умеет:**

- Статические уровни, включение на время, непрерывное мигание (произвольными
  уровнями), пользовательские последовательности (SOS, двойное мигание).
- 12 встроенных глобальных эффектов с авто-повтором и авто-остановкой.
- Упакованные команды 32 бит (4 байта на пару фаз + счётчик повторов).
- Арбитраж доступа к индикатору между подсистемами (владение).
- События переходов (по запросу, модулем `LED_USE_EVENTS`).
- Отключаемые модули (`LED_USE_*`) для экономии Flash.

## Быстрый старт

### 1. Подключение библиотеки

Скопируйте `include/led.h` и `src/led.c` в свой проект (или подключите
репозиторий как PlatformIO-библиотеку — см. `library.json`).

### 2. Реализация callback для вывода

```c
#include "led.h"

void led_hw_set(uint8_t id, uint8_t level) {
    /* level == 0 -> погасить, level > 0 -> «горит» */

    // GPIO-включатель:
    if (level) GPIO_SetBits(GPIOC, (uint16_t)(1UL << (4 + id)));
    else      GPIO_ResetBits(GPIOC, (uint16_t)(1UL << (4 + id)));

    // DAC с N ступенями:
    // if (level > LED_LEVEL_MAX) level = LED_LEVEL_MAX;
    // out_set_stc(dac_code[level]);
}
```

### 3. Инициализация и главный цикл

```c
int main(void) {
    SystemInit();
    gpio_init();

    led_init();
    led_set_callback(led_hw_set);

    led_blink(0, 15, 15);  /* ~250 мс вкл / ~250 мс выкл (тик ≈ 16 мс) */

    while (1) {
        led_process();     /* = led_advance(1), 60 раз в секунду */
        Delay_Ms(16);
    }
}
```

## Модель времени: `led_advance` и `led_ticks_until_next`

```c
void     led_advance(uint32_t ticks);
uint32_t led_ticks_until_next(void);
void     led_process(void);          /* = led_advance(1) */
```

Это единственная модель времени в библиотеке. Ни таймеров, ни SysTick, ни
делителя частоты внутри нет.

**Контракт `led_advance(ticks)`:** после возврата состояние всех выходов
соответствует времени `t + ticks`.

- Если за один вызов пересечено несколько переходов (смена фазы мигания,
  конец шага последовательности, переход упакованной команды), они
  применяются **все и по порядку** — через callback, детерминированно.
  Переход не «пропускается».
- `led_advance(0)` время не двигает (но может выполнить синхронизацию
  выводов — см. `led_refresh()`).
- Тики без переходов проматываются за O(1) на тик: полный перебор каналов
  делается только на тиках, где что-то происходит.

**Инвариант против дрейфа:**

```c
for (i = 0; i < N; i++) led_advance(1);   /* тик за тиком  */
led_advance(N);                           /* одним вызовом */
```

Обе последовательности дают **идентичный набор вызовов callback** и одинаковое
 конечное состояние. Это проверяется тестами для всех режимов
(`test_advance_invariant()`).

**`led_ticks_until_next()`** возвращает число тиков до ближайшего **изменения
вывода**:

- `LED_TICKS_FOREVER` — таймерных паттернов нет, изменения возможны только
  после нового вызова API;
- значение **никогда не равно 0**: стартовые мутаторы (например
  `led_blink()`) применяют первое состояние немедленно;
- возвращается минимум по всем активным паттернам.

Особый случай: при активном глобальном эффекте возвращается 1 (эффекты тикают
по одному тику — их счётчики связаны модульной арифметикой, быстрый проход по
ним потребовал бы деления в `led_advance()`).

**Уровни задаются в тиках**, а не в миллисекундах: библиотека не знает частоту
вызова и не пересчитывает ничего в физическое время. 60 Гц, 1 кГц или 1 МГц —
всё равно.

## Спящий хост

```c
while (led_ticks_until_next() != LED_TICKS_FOREVER) {
    program_wakeup_timer(led_ticks_until_next());  /* тик = ваша единица */
    sleep();
    led_advance(elapsed_ticks);                    /* сколько реально прошло */
}
```

Почему это корректно:

1. За время сна переходов не было (иначе `led_ticks_until_next()` вернуло бы
   меньше), поэтому состояние выходов не изменилось «само».
2. Все переходы, пересечённые за `elapsed_ticks`, будут применены по порядку
   внутри одного `led_advance()` — даже если их было несколько.
3. Если сон продлился дольше (таймер сработал с задержкой), лишние тики
   без переходов ничего не меняют, поэтому «перелёт» безопасен.

Аналог с учётом «просрочки»:

```c
uint32_t wait = led_ticks_until_next();
if (wait == LED_TICKS_FOREVER) { wait = IDLE_PERIOD; }
program_wakeup_timer(wait);
sleep();
led_advance(elapsed_ticks);   /* elapsed может быть > wait — это нормально */
```

## Уровни вывода

Каждый канал выводит **уровень** 0..`LED_LEVEL_MAX` (по умолчанию 7), а не
логический 0/1:

| Уровень | Смысл |
|---------|-------|
| 0 | выключено |
| 1..`LED_LEVEL_MAX` | включено с яркостью/режимом N |

Интерпретация уровня — забота callback'а: включить пин, записать код в DAC,
задать скважность ШИМ. Библиотека уровни не проверяет и не подрезает
(при `LED_LEVEL_MAX = 7` поле уровня в упакованных командах как раз 3 бита).

Типичные случаи:

```c
led_set_level(0, 5);        /* статическая яркость (аналоговый канал) */
led_on(0);                  /* = led_set_level(0, 1) */
led_off(0);                 /* = led_set_level(0, 0) */

led_blink_level(0, 5, 15, 0, 45);   /* вспышка на текущей яркости + гашение */
led_get_level(0);                   /* текущий уровень вывода */
led_is_on(0);                       /* уровень > 0 */
led_toggle(0);                      /* переключение по «уровень > 0» */
```

`led_toggle()` работает по **фактическому уровню вывода**: горящий диод в любом
режиме (мигание, ON_FOR, эффект) будет погашен, а не «включён ещё раз».

## Модель вызовов и потокобезопасность

Внутреннее состояние — обычные static-переменные без блокировок.
Поддерживаются два сценария:

**1) Один контекст (по умолчанию).** Все `led_*()` вызываются из одного места —
обычно из главного цикла. Настройка не требуется.

**2) `led_advance()` в прерывании, остальной API — из главного цикла.**
Определите критическую секцию до подключения `led.h`:

```c
#define LED_ENTER_CRITICAL()  __disable_irq()
#define LED_EXIT_CRITICAL()   __enable_irq()
#include "led.h"
```

или через флаги сборки:

```ini
build_flags =
    -DLED_ENTER_CRITICAL='portENTER_CRITICAL()'
    -DLED_EXIT_CRITICAL='portEXIT_CRITICAL()'
```

Мутаторы (`led_on`, `led_blink`, `led_play`, эффекты, упакованные команды,
`led_init`, `led_set_callback`, `led_refresh`, owner-API) становятся атомарными
относительно обработчика. Внимание: при заданных макросах пользовательские
callback'и могут вызываться с запрещёнными прерываниями — держите их короткими.

`led_advance()` критической секцией **НЕ** оборачивается намеренно: это
сохраняет минимальную задержку реакции на прерывания и на «спящий» хост.

**Не поддерживается:** вызов мутаторов из прерывания, когда `led_advance()`
работает в главном цикле — состояние конечного автомата будет повреждено.

**Из callback нельзя вызывать функции `led_*()`** — библиотека не реентерабельна.

## Конфигурация

| Макрос | По умолчанию | Описание |
|--------|--------------|----------|
| `LED_COUNT` | 4 | Число каналов, 1..8 (проверка `#error`) |
| `LED_LEVEL_MAX` | 7 | Диапазон уровней вашей аппаратуры, 1..255 |
| `LED_USE_SEQUENCES` | 1 | `led_play()` и режим SEQUENCE (экономит 10 Б на канал при 0) |
| `LED_USE_EFFECTS` | 1 | вся подсистема глобальных эффектов |
| `LED_USE_RUNNING_EFFECTS` | 1 | RUNNING_FWD / BWD / CIRCLE |
| `LED_USE_PINGPONG_EFFECT` | 1 (0 при LED_COUNT=1) | RUNNING_PP |
| `LED_USE_BLINK_EFFECTS` | 1 | EMERGENCY / PAIR_BLINK / ALTERNATING |
| `LED_USE_MULTI_BLINK_EFFECTS` | 1 | DOUBLE_BLINK / TRIPLE_BLINK |
| `LED_USE_RANDOM_EFFECT` | 1 | RANDOM_FLASH |
| `LED_USE_HOLD_EFFECTS` | 1 | RUNNING_FWD/BWD_HOLD |
| `LED_USE_PACKED_COMMANDS` | 1 | упакованные команды 32 бит |
| `LED_USE_EVENTS` | 0 | события переходов |
| `LED_ENTER/EXIT_CRITICAL` | пусто | критическая секция |

Значения enum `led_effect_t` / `led_mode_t` / `led_owner_t` / `led_event_t` не
зависят от отключённых модулей: попытка запустить отключённый эффект
игнорируется, ABI стабилен.

**Типичная конфигурация «спящего» хоста:**

```ini
build_flags =
    -DLED_COUNT=3
    -DLED_LEVEL_MAX=7
    -DLED_USE_EFFECTS=0
    -DLED_USE_SEQUENCES=0
    -DLED_USE_EVENTS=0
```

## API справочник

### Инициализация

```c
void led_init(void);
```

Сбрасывает все каналы в OFF, обнуляет счётчики и PRNG, останавливает эффект,
снимает владение индикатором. Callback **сохраняется**, кэш выводов
инвалидируется — на ближайшем `led_advance()` все выводы будут принудительно
перезаписаны (в том числе погашены). Отключить вывод: `led_set_callback(NULL)`.

```c
void led_set_callback(led_set_fn fn);
```

Устанавливает callback. Инвалидирует кэш уровней: новый обработчик получит
полную картину (по одному вызову на каждый канал) на ближайшем `led_advance()`.

```c
void led_refresh(void);
```

Принудительная пересинхронизация выводов без смены логического состояния.
Нужна, если выводы могли измениться в обход библиотеки: переинициализация
порта, выход из сна, смена альтернативной функции пина. Следующий
`led_advance()` перезапишет все каналы теми же уровнями.

### Время

```c
void     led_advance(uint32_t ticks);
uint32_t led_ticks_until_next(void);
void     led_process(void);
```

См. раздел «Модель времени».

### Управление отдельным каналом

```c
void led_set_level(uint8_t id, uint8_t level);
void led_on(uint8_t id);              /* = led_set_level(id, 1) */
void led_off(uint8_t id);             /* = led_set_level(id, 0) */
void led_toggle(uint8_t id);
void led_on_for(uint8_t id, uint16_t ticks);
void led_blink(uint8_t id, uint16_t on_ticks, uint16_t off_ticks);
void led_blink_level(uint8_t id, uint8_t on_level, uint16_t on_ticks,
                     uint8_t off_level, uint16_t off_ticks);
#if LED_USE_SEQUENCES
void led_play(uint8_t id, const led_sequence_t *seq);
#endif
void led_flash_and_fade(uint8_t count);
```

Все мутаторы отменяют текущий режим канала (в том числе участие в эффекте и в
упакованном паттерне). Индекс вне диапазона игнорируется.

| Вызов | Что происходит |
|-------|----------------|
| `led_set_level(id, L)` | статический уровень L, любой таймер отменяется |
| `led_on(id)` / `led_off(id)` | уровень 1 / 0 |
| `led_toggle(id)` | уровень > 0 → OFF, иначе → ON |
| `led_on_for(id, N)` | уровень 1 на N тиков, затем OFF |
| `led_blink(id, a, b)` | мигание уровнями 1/0 |
| `led_blink_level(id, l1, a, l2, b)` | мигание уровнями l1/l2 |
| `led_play(id, seq)` | воспроизведение последовательности |
| `led_flash_and_fade(n)` | n каналов ON 60 тиков → гаснут по одному с шагом 10 |

`led_flash_and_fade(count)` включает каналы 0..count-1 одновременно, держит
1 секунду (60 тиков), затем гасит по одному с интервалом 10 тиков: **канал
count-1 гаснет первым, канал 0 — последним**. Останавливает активный эффект и
гасит каналы с индексом >= count.

### Запросы состояния

```c
led_mode_t led_get_mode(uint8_t id);
uint8_t    led_get_level(uint8_t id);
uint8_t    led_is_on(uint8_t id);
uint8_t    led_any_led_active(void);
uint8_t    led_pattern_active(void);
#if LED_USE_EFFECTS
uint8_t    led_effect_active(void);
uint32_t   led_effect_remaining(void);
#endif
```

`led_get_level()` отражает кэшированный уровень вывода и работает даже без
подключённого callback'а. `led_any_led_active()` учитывает только ручные режимы
каналов, `led_pattern_active()` — ещё эффект и упакованные команды (это то,
что нужно для арбитража владения).

## Работа с последовательностями

### Определение

```c
typedef struct {
    uint8_t  level;   /* уровень вывода: 0 = off, 1..LED_LEVEL_MAX */
    uint16_t ticks;   /* длительность (0 трактуется как 1 тик)     */
} led_step_t;

typedef struct {
    const led_step_t *steps;   /* массив шагов (должен «жить» долго) */
    uint16_t          count;   /* количество шагов                  */
    bool              loop;    /* true = зациклить                  */
} led_sequence_t;
```

Порядок полей `led_step_t` выбран так, чтобы размер структуры был 4 байта на
RV32 (выравнивание `uint16_t` = 2) без «дырки».

### Пример: SOS

```c
static const led_step_t sos_steps[] = {
    LED_STEP_ON(6),   LED_STEP_OFF(6),      /* .  */
    LED_STEP_ON(6),   LED_STEP_OFF(6),      /* .  */
    LED_STEP_ON(6),   LED_STEP_OFF(18),     /* . + пауза */
    LED_STEP_ON(18),  LED_STEP_OFF(6),      /* -  */
    LED_STEP_ON(18),  LED_STEP_OFF(6),      /* -  */
    LED_STEP_ON(18),  LED_STEP_OFF(18),     /* - + пауза */
    LED_STEP_ON(6),   LED_STEP_OFF(6),      /* .  */
    LED_STEP_ON(6),   LED_STEP_OFF(6),      /* .  */
    LED_STEP_ON(6),   LED_STEP_OFF(60),     /* . + пауза между повторами */
};
static const led_sequence_t sos_seq = LED_SEQ_LOOP(sos_steps);

led_play(2, &sos_seq);
```

> **Важно:** библиотека хранит указатель на массив шагов и не копирует его.
> Массив должен существовать всё время воспроизведения — используйте
> `static const`, а не локальные переменные.

### Макросы

| Макрос | Назначение |
|--------|-----------|
| `LED_STEP_ON(ticks)` | шаг «уровень 1 на N тиков» |
| `LED_STEP_OFF(ticks)` | шаг «уровень 0 на N тиков» |
| `LED_STEP_LVL(level, ticks)` | шаг с произвольным уровнем |
| `LED_ARRAY_LEN(arr)` | длина массива |
| `LED_SEQ(steps)` | `led_sequence_t` без зацикливания |
| `LED_SEQ_LOOP(steps)` | `led_sequence_t` с зацикливанием |

Длительность шага с `ticks == 0` трактуется как 1 тик.

### Стартовая задержка

Отдельного API «старт через N тиков» нет намеренно: он не нужен, потому что
первый шаг применяется немедленно. Достаточно ведущего шага `LED_STEP_OFF(n)`:

```c
static const led_step_t late_start[] = {
    LED_STEP_OFF(40),     /* 40 тиков тишины, потом паттерн */
    LED_STEP_LVL(3, 2),
    LED_STEP_OFF(8)
};
static const led_sequence_t late = LED_SEQ(late_start);
led_play(0, &late);
```

## Глобальные эффекты

Эффекты управляют **всеми каналами** одновременно. Значения enum не зависят
от конфигурации; попытка запустить эффект из отключённого модуля
(`LED_USE_* = 0`) игнорируется.

### Встроенные эффекты

| Эффект | Описание | Цикл |
|--------|----------|------|
| `LED_EFFECT_RUNNING_FWD` | Бегущий огонь 0→N-1 | N×10 тиков |
| `LED_EFFECT_RUNNING_BWD` | Бегущий огонь N-1→0 | N×10 |
| `LED_EFFECT_RUNNING_PP` | Туда-обратно | (2N−2)×10 |
| `LED_EFFECT_RUNNING_CIRCLE` | Бегущий огонь быстрее | N×8 |
| `LED_EFFECT_PAIR_BLINK` | Чёт/нечет в противофазе | 30 |
| `LED_EFFECT_EMERGENCY` | Все диоды 5/5 тиков | 10 |
| `LED_EFFECT_RANDOM_FLASH` | Случайные вспышки (xorshift32) | 1 тик |
| `LED_EFFECT_DOUBLE_BLINK` | Двойное мигание | 80 |
| `LED_EFFECT_TRIPLE_BLINK` | Тройное мигание | 105 |
| `LED_EFFECT_ALTERNATING` | Чёт/нечет, медленно | 40 |
| `LED_EFFECT_RUNNING_FWD_HOLD` | Бег + пауза 20 + удержание 45 | N×10+65 |
| `LED_EFFECT_RUNNING_BWD_HOLD` | То же назад | N×10+65 |

При LED_COUNT = 4 это даёт таблицу 40/40/60/32/30/10/1/80/105/40/105/105.
Маски чёт/нечет и все периоды производные от `LED_COUNT` и работают для
любого N.

### Запуск и остановка

```c
led_start_effect(LED_EFFECT_RUNNING_FWD);          /* бесконечно, идемпотентно */
led_start_effect_for(LED_EFFECT_EMERGENCY, 5);     /* 5 вспышек, авто-стоп    */
led_start_effect_for(LED_EFFECT_RUNNING_FWD, 0);   /* 0 = бесконечно          */
led_restart_effect_for(LED_EFFECT_RUNNING_FWD, 1); /* принудительно с нуля    */
led_stop_effect();                                  /* вручную                 */
```

**Идемпотентность.** `led_start_effect()` / `led_start_effect_for()` не
изменяют состояние, если этот же эффект уже активен, — их безопасно вызывать
в цикле опроса. Для принудительного перезапуска (кнопка, новая ошибка)
используйте `led_restart_effect_for()`.

**Каналы можно «оторвать»** от эффекта любым per-LED вызовом — остальные
продолжат эффект. Вернуть канал в эффект без перезапуска нельзя.

**Таймер повторов тикает независимо от каналов:** если все каналы «оторваны»,
эффект всё равно завершится вовремя (`led_effect_remaining()` показывает
остаток).

## Упакованные команды

### Зачем

Обычная последовательность стоит **4 байта на фазу** (`led_step_t`), причём
каждый шаг хранит и уровень, и длительность. Упакованная команда стоит
**4 байта на пару фаз** и несёт сразу: маску каналов, счётчик повторов,
длительности обеих фаз и оба уровня. Для таблиц маяков/стробов это вдвое
меньше данных и не нужен `const`-массив в RAM при вычислении на месте.

Цена — код: конечный автомат упакованных команд заметно больше кода, чем
подсистема последовательностей (измерения — в разделе «Потребление
ресурсов»). Если таблицы паттернов в RAM/RAM-таблицах не ограничены,
последовательности могут оказаться выгоднее.

### Формат слова (32 бита)

```
 [3:0]   device    — битовая маска каналов (лишние биты сверх LED_COUNT
                   отсекаются)
 [7:4]   count     — число повторов пары фаз; 15 = бесконечно
 [10:8]  shift0    — порядок масштаба длительности фазы 0 (0..7)
 [16:11] win0      — мантисса длительности фазы 0 (0..63)
 [19:17] shift1    — порядок масштаба длительности фазы 1
 [25:20] win1      — мантисса длительности фазы 1
 [28:26] level0    — уровень фазы 0 (0 = off, 1..7)
 [31:29] level1    — уровень фазы 1
```

Длительность в **тиках**: `duration = (1 << (2 * shift)) * win`, то есть
шаг ×1, ×4, ×16, ×64, ×256, ×1024, ×4096, ×16384 при `win` 0..63.
`win == 0` — фаза без ожидания.

Диапазон 1..1032192 тиков. Точность: значения до 63 тиков кодируются **точно**;
для остальных round-to-nearest даёт относительную погрешность не хуже
**1/32 ≈ 3.1 %** (теоретический предел для 6-битной мантиссы при шаге 4^shift:
мантисса лежит в диапазоне 16..63, шаг квантования — ticks/16, ошибка
округления — половина шага). Максимум достигается сразу над границей
диапазона, например 4065 тиков → 4096 (+0.76 %).

### Сборка команды

```c
LED_CMD(dev, count, t0, t1, lvl0, lvl1)   /* одно 32-битное слово */
```

* `dev` — битовая маска каналов (0..15);
* `count` — число повторов пары фаз (0..15, 15 = бесконечно; 0 и 1 дают одну пару);
* `t0`, `t1` — длительности фаз в тиках (0 = без ожидания);
* `lvl0`, `lvl1` — уровни фаз (0..7).

Длительность кодируется макросом `LED_TIME_ENC(t)` **внутри `LED_CMD`**, делить
вручную ничего не нужно. Деление есть только в макросе и только при сборке;
в рантайме разбор команды — это сдвиги.

### Системные команды

Системная команда — слово, у которого биты 5..31 равны нулю:
`op[1:0]` и `steps[4:2]`. Нулевое слово — это `LED_SYS_STOP`.

| Макрос | Смысл на границе массива |
|--------|-------------------------|
| `LED_SYS_STOP` | завершить паттерн (по умолчанию, если явной команды нет) |
| `LED_SYS_REP_START` | повторять массив с первой команды (бесконечно) |
| `LED_SYS_REP_AT(n)` | повторить массив ещё `n` раз (n = 0..7), затем STOP |

Системные команды исполняются немедленно в любой точке массива, а не только
в конце. `LED_PACKED_GUARD` ограничивает число системных команд за один
переход — вырожденная таблица из одних системных команд (или с нулевыми
фазами) не может закрутить бесконечный цикл внутри одного `led_advance()`.

### API

```c
void led_packed_run(const uint32_t cmds[], uint16_t count);
void led_packed_once(uint32_t cmd);
void led_packed_stop(void);
```

- `led_packed_run()` запускает массив (массив не копируется и должен
  существовать всё время исполнения). Каналы из маски `device` **первой**
  команды переводятся в `LED_MODE_PACKED` — паттерн **забирает** их себе, как
  глобальный эффект; каналы вне маски не трогаются. Забрать канал (или
  отдать свой паттерн) можно любым per-LED вызовом — после этого паттерн к
  нему не обращается до конца паттерна, и команды с более широкой маской
  его уже не получают.
- `led_packed_once()` исполняет одну команду, вычисленную в рантайме.
- `led_packed_stop()` останавливает паттерн без участия владения.

### Пример: маяк

```c
static const uint32_t beacon[] = {
    LED_CMD(0x1, 1, 15,  60, 3, 0),   /* 1-я вспышка: 15 тиков горит */
    LED_CMD(0x1, 1, 15, 420, 3, 0),   /* 2-я вспышка + длинная пауза */
    LED_CMD(0x1, 1, 15,  60, 3, 0),   /* 3-я вспышка */
    LED_SYS_REP_START                 /* повторять до снятия владения */
};

if (led_claim() == LED_OWNER_NONE) {
    led_set_owner(LED_OWNER_BEACON);
    led_packed_run(beacon, LED_ARRAY_LEN(beacon));
}
```

### Статические проверки формата

Раскладка слова проверяется на этапе компиляции (`_Static_assert` в C11,
эквивалентный приём в строгом C99): отсутствие пересечений и пропусков
битовых полей, нулевое слово = STOP, эталонное значение команды и round-trip
кодирование/декодирование длительностей.

## Владение индикатором

Индикатор один, но управляют им несколько подсистем (обычная индикация, маяк,
предупреждение, строб). Арбитраж — на уровне подсистем, а не выводов: маяк
умеет гасить «своё» целиком и не трогает чужое.

```c
typedef uint8_t led_owner_t;
enum {
    LED_OWNER_NONE = 0, LED_OWNER_UI = 1, LED_OWNER_BEACON = 2,
    LED_OWNER_WARNING = 3, LED_OWNER_STROBE = 4
};

void        led_set_owner(led_owner_t owner);
led_owner_t led_claim(void);
void        led_release(led_owner_t owner);
uint8_t     led_stop_owner(led_owner_t owner);
uint8_t     led_pattern_active(void);
```

Правила:

- **Владение глобальное для подсистемы**, не per-канал. Если маяк работает на
  двух каналах, `led_stop_owner(LED_OWNER_BEACON)` гасит оба.
- Владение **не проверяется автоматически**: можно «съесть» чужой паттерн,
  если не проверить `led_claim()`. Ответственность на хосте.
- Владение снимается само, когда все таймерные паттерны завершились (проверка —
  в конце `led_advance()`), а также явно через `led_release()` и
  `led_stop_owner()`.
- Следствие: **объявлять владение нужно вместе с запуском паттерна**, одним
  блоком кода. Владение, заявленное без паттерна, снимается ближайшим
  `led_advance()`.
- `led_stop_owner()` останавливает все таймерные паттерны (ON_FOR/BLINK/
  SEQUENCE, эффект, упакованные команды) и снимает владение, если владелец
  совпал; возвращает 1 в этом случае, иначе 0 (аналог «stop if mode == X»).
  Статичные режимы `LED_MODE_ON`/`OFF` не трогаются — это явное решение хоста.
- `led_pattern_active()` — «идёт ли сейчас индикация» (учитывает и эффект, и
  упакованные команды). Удобно, чтобы не запускать вторую подсистему поверх
  первой и чтобы хост знал, стоит ли будить МК.

## События

Компилируются при `LED_USE_EVENTS = 1` (по умолчанию **0**, чтобы не раздувать
базовую сборку; владение индикатором работает и без событий).

```c
typedef enum {
    LED_EV_CYCLE_START,   /* начался цикл паттерна; arg = номер повтора */
    LED_EV_PATTERN_END,   /* паттерн завершился;      arg = 0           */
    LED_EV_STATE          /* уровень вывода изменился; arg = нов. уровень */
} led_event_t;

typedef void (*led_event_fn)(uint8_t id, led_event_t ev, uint32_t arg);
void led_set_event_callback(led_event_fn fn);
```

Когда приходят события:

| Событие | Когда |
|---------|-------|
| `LED_EV_CYCLE_START` | старт паттерна и каждый его круг (`arg` = номер повтора) |
| `LED_EV_PATTERN_END` | паттерн дошёл до конца (таймер канала, конец последовательности, остановка эффекта, STOP упакованной команды) |
| `LED_EV_STATE` | изменение уровня вывода (`arg` = новый уровень) |

Для глобальных паттернов (эффект, упакованные команды) `id` = младший канал
маски — идентификатора «подсистемы» у глобального паттерна нет.

Типичное применение: «замерить АКБ на границе цикла маяка» — в
`LED_EV_CYCLE_START` считать напряжение.

Из callback нельзя вызывать `led_*()` (та же нерентерабельность, что у
callback'а вывода).

## Приоритеты управления

| Вызов | Что происходит |
|-------|----------------|
| `led_set_level(id, L)` | статический уровень, таймер отменяется |
| `led_on(id)` / `led_off(id)` | уровень 1 / 0 |
| `led_toggle(id)` | уровень > 0 → OFF, иначе → ON |
| `led_on_for(id, N)` | отменяет предыдущий → ON_FOR |
| `led_blink(id, ...)` | отменяет предыдущий → BLINK (уровни 1/0) |
| `led_blink_level(id, ...)` | отменяет предыдущий → BLINK (произвольные уровни) |
| `led_play(id, seq)` | отменяет предыдущий → SEQUENCE |
| `led_start_effect(...)` | все каналы в EFFECT (идемпотентно) |
| `led_start_effect_for(..., N)` | все каналы в EFFECT на N циклов |
| `led_restart_effect_for(..., N)` | перезапуск эффекта с нулевой фазы |
| `led_stop_effect()` | каналы в EFFECT → OFF |
| `led_packed_run(...)` | каналы маски `device` → LED_MODE_PACKED (управляет паттерн) |
| `led_packed_stop()` | каналы паттерна → OFF |
| `led_flash_and_fade(count)` | count каналов ON 60 тиков → гаснут по одному |
| `led_stop_owner(owner)` | все таймерные паттерны → OFF, владение снято |
| `led_refresh()` | кэш выводов сброшен, выводы перезапишутся |

## Примеры использования

### Базовый

```c
led_init();
led_set_callback(led_hw_set);

led_on(0);
led_blink(1, 15, 15);
led_on_for(2, 300);

while (1) {
    led_process();
    Delay_Ms(16);
}
```

### Разные частоты на разных диодах

Самый частый вопрос: «а если диоды должны мигать с разными частотами?»
Да — это и есть основной сценарий, у каждого канала свой автомат.
Рабочий пример — `examples/rates_ch32v003`:

```c
/* тик = 1 мс, скважность 50 % */
static const uint16_t period_ticks[4] = { 4000u, 2000u, 1000u, 500u };

for (uint8_t id = 0; id < LED_COUNT; id++) {
    uint16_t half = (uint16_t)(period_ticks[id] / 2u);
    led_blink(id, half, half);
}

for (;;) {
    led_advance(1u);
    Delay_Ms(1u);
}
```

Проверено тестом `test_independent_rates()`: за 4 с — ровно 1/2/4/8
вспышек, каждая ровно на половину периода, начало вспышек на тиках
1, 1+period, 1+2·period, … (точного тайминга без накопления ошибки), и
пакетный `led_advance(10)` даёт тот же результат, что и тик за тиком.

**Два ограничения, о которых стоит знать заранее:**

1. **Тик должен быть заметно быстрее самой быстрой частоты.** Вспышка
   100 мс раз в 500 мс требует тика не грубее 10–50 мс; тик 1 мс берёт
   запас. Наоборот, тик 1 с для такой задачи не годится.
2. **Период должен помещаться в таймер канала** (`uint16_t`, до 65535
   тиков). При тике 1 мс это 65 секунд — задача «мигает раз в две минуты»
   в эту конфигурацию не помещается. Варианты: снизить частоту тика
   (100 мс → период до 1.8 часа) или перейти на упакованные команды
   (32-битный таймер, до 1032192 тиков).

Если одного мигания на период мало (маяк из трёх вспышек, SOS и т.п.) —
это уже паттерн, см. [последовательности](#работа-с-последовательностями) и
[упакованные команды](#упакованные-команды).

### Аналоговый канал с яркостями

```c
static const uint8_t dac_code[LED_LEVEL_MAX + 1] = {0, 34, 68, 102, 136, 170, 204, 238};

void led_hw_set(uint8_t id, uint8_t level) {
    if (level > LED_LEVEL_MAX) level = LED_LEVEL_MAX;
    if (id == 0) out_set_stc(dac_code[level]);   /* основной фонарь */
    else         gpio_write(id - 1, level != 0);
}

led_set_level(0, 3);                     /* нормальный режим */
led_blink_level(0, 3, 15, 0, 45);        /* вспышка + гашение */
```

### Спящий МК с таймером пробуждения

```c
#define TICK_MS 1u

void SysTick_Handler(void) { /* 1 кГц */ g_ms++; }

int main(void) {
    for (;;) {
        uint32_t wait = led_ticks_until_next();
        uint32_t now, then;

        if (wait == LED_TICKS_FOREVER) wait = 100u;   /* простой сон */
        now = g_ms;
        sleep_ms(wait);
        then = g_ms;

        led_advance((then - now) * TICK_MS);   /* тик = 1 мс */
    }
}
```

### Эффект по событию (идемпотентный опрос)

```c
while (1) {
    if (alarm_active()) {
        /* повторный запуск по каждому событию: */
        led_restart_effect_for(LED_EFFECT_EMERGENCY, 10);
    }
    led_process();
    Delay_Ms(16);
}
```

### Маяк как подсистема

```c
static void beacon_start(void) {
    if (led_claim() != LED_OWNER_NONE) return;   /* индикатор занят */
    led_set_owner(LED_OWNER_BEACON);
    led_off(0);                                    /* освободить свой канал */
    led_packed_run(beacon, LED_ARRAY_LEN(beacon));
}

static void beacon_stop(void) {
    if (led_stop_owner(LED_OWNER_BEACON)) {
        led_blink(0, 15, 15);                      /* вернуть обычный режим */
    }
}

static bool is_aux_mode(void) {
    return led_claim() == LED_OWNER_BEACON;
}
```

## Портирование на другие МК

1. **Скопировать** `include/led.h` и `src/led.c`
2. **Реализовать callback** `led_hw_set()` для вашего GPIO/DAC
3. **Выбрать тик** и реализовать его подачу: `led_process()` (опрос) или
   `led_advance(n)` (таймер пробуждения)

**STM32 (HAL):**
```c
static const uint16_t led_pins[] = { GPIO_PIN_0, GPIO_PIN_1, GPIO_PIN_2, GPIO_PIN_3 };

void led_hw_set(uint8_t id, uint8_t level) {
    if (id >= LED_COUNT) return;
    HAL_GPIO_WritePin(GPIOC, led_pins[id],
                      (level != 0u) ? GPIO_PIN_SET : GPIO_PIN_RESET);
}
```

**AVR (ATmega328P):**
```c
void led_hw_set(uint8_t id, uint8_t level) {
    if (id >= LED_COUNT) return;
    if (level) PORTB |= (1 << id);
    else       PORTB &= ~(1 << id);
}
```

**ESP32 (ESP-IDF):**
```c
void led_hw_set(uint8_t id, uint8_t level) {
    gpio_set_level(GPIO_NUM_2 + id, (level != 0u) ? 1 : 0);
}
```

## Потребление ресурсов

Измерено на CH32V003 (RISC-V RV32EC, -Os, WCH NoneOS SDK). Вклад библиотеки
посчитан как разница «сборка с библиотекой минус сборка без неё» при том же
окружении; прошивка демо целиком (SDK + демо) — 3968 Б Flash, 412 Б RAM
(штатная сборка `ch32v003`, диагностика выключена: `-DDEMO_UART=0
-DDEMO_SELFTEST=0`). С включённой диагностикой — 11520 Б Flash, 976 Б RAM.

| Конфигурация | Flash | RAM |
|--------------|-------|-----|
| 1 канал, только упакованные команды (эффекты/последовательности выключены) | 1244 Б | 48 Б |
| 3 канала, то же | 1532 Б | 68 Б |
| 1 канал, только последовательности (альтернатива) | 792 Б | 28 Б |
| 1 канал, оба модуля | 1408 Б | 56 Б |
| 1 канал, подмножество ТЗ целиком (+последовательности, +события) | 1620 Б | 60 Б |
| 4 канала, все модули | 2660 Б | 124 Б |

Разложение (1 канал, производные величины): общее ядро ≈ 660 Б, модуль
упакованных команд ≈ 580 Б, модуль последовательностей ≈ 130 Б.

**Как читать эти цифры.** Упакованные команды экономят *данные*: 4 байта на пару
фаз счёта/маски/уровней против 4 байтов на каждую фазу последовательности
(фактически 8 байт на пару фаз, если фазы различаются уровнем). Но их конечный
автомат заметно больше по коду. Если ограничение — Flash, а таблицы паттернов
живут во Flash и не в RAM, обычные последовательности могут быть выгоднее;
если ограничение — RAM или объём констант в ОЗУ, упакованные команды выигрывают.
В конфигурации заказчика (`LED_COUNT=3`, только упакованные команды) вклад
библиотеки — 1532 Б Flash и 68 Б RAM.

Неиспользуемые функции выбрасываются линкером (`-ffunction-sections`
+ `--gc-sections`), поэтому реальный вклад пропорционален числу вызываемых
API-функций: неиспользуемый `led_play()` при `LED_USE_SEQUENCES=0` и
неиспользуемые `led_toggle()`/`led_get_mode()` не стоят ничего.

### RAM

| Компонент | Размер |
|-----------|--------|
| `leds[LED_COUNT]` | 20 Б на канал с последовательностями, 10 Б без них |
| Глобальное состояние ядра | ~22 Б (hw_set, кэш уровней, маски, владелец) |
| Конечный автомат упакованных команд | 21 Б (независимо от `LED_COUNT`) |
| Состояние эффекта | 13 Б (независимо от `LED_COUNT`) |

### Flash

Фактический размер зависит от платформы и от того, какие API реально
используются: неиспользуемые функции выбрасываются линкером
(`-ffunction-sections -fdata-sections` + `--gc-sections`).

### Время выполнения

- `led_advance(n)`: O(LED_COUNT) на тик с переходом, O(1) на тик без перехода.
- Ни деления, ни умножения в рантайме (деление есть только в макросах
  кодирования длительностей и сворачивается при сборке).
- При активном эффекте `led_advance(n)` = n × `led_advance(1)`.

## Тесты

```bash
pio test -e native    # либо: gcc -std=c99 -Iinclude \
                      #   test/test_led_lib/test_led_lib.c src/led.c -o t && ./t
```

Самодостаточный раннер (никаких внешних тест-фреймворков), ~380 проверок в
конфигурации по умолчанию. Набор адаптируется к `LED_COUNT` и `LED_USE_*`.

Покрытие:

- тайминги ON_FOR / BLINK / BLINK_LEVEL / SEQUENCE (посимвольно, с учётом
  момента применения уровня);
- run-length и периоды всех 12 эффектов, идентичность циклов HOLD-эффектов;
- идемпотентность запуска, таймер повторов (включая сценарий «все каналы
  оторваны»), авто-стоп, `led_restart_effect_for()`;
- **инвариант `led_advance(1)×N == led_advance(N)`** для всех режимов
  (сравниваются и последовательность вызовов callback, и конечное состояние);
- **`led_ticks_until_next()`**: ноль не возвращается, переходы не пропускаются,
  сценарий «сон до следующего изменения» даёт тот же поток вызовов;
- уровни: `led_set_level`, `led_blink_level`, уровневые шаги, работа
  `led_get_level()` без callback'а;
- владение: захват, снятие, `led_stop_owner()` (свой/чужой), авто-снятие,
  `led_init()` снимает владение;
- упакованные команды: статические проверки раскладки, round-trip кодирования,
  тайминги эталонного маяка, `STOP`/`REP_START`/`REP_AT(n)`, guard от
  вырожденных таблиц, маска каналов, `led_packed_once()`;
- события (при `LED_USE_EVENTS=1`): циклы, завершение, уровни;
- нулевые длительности, некорректные аргументы (все `id` вне диапазона,
  `NULL`-массивы, значения эффекта вне enum, системы без флагов);
- пересинхронизация выводов, сохранение callback'а при `led_init()`.

CI прогоняет матрицу конфигураций (LED_COUNT 1..8 × `LED_USE_*`, уровни,
комбинации) с `-Wall -Wextra -Wconversion -Wpedantic -Werror` плюс отдельную
проверку библиотеки с `-pedantic-errors` и сборку прошивки CH32V003.

## Миграция с 2.x

1. **Callback вывода**: `void (*)(uint8_t id, bool state)` →
   `void (*)(uint8_t id, uint8_t level)`. В теле: `if (state)` → `if (level)`.
2. **Инициализаторы шагов**: `{ true, 10 }` → `{ 1, 10 }`,
   `{ false, 5 }` → `{ 0, 5 }`. Макросы `LED_STEP_ON/OFF` не изменились.
3. Всё остальное совместимо: `led_process()` = `led_advance(1)`, эффекты,
   запросы состояния, `led_refresh()`, критическая секция.
